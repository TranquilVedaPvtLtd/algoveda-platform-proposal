Section 1

Parties

This Statement of Work ("SOW") is entered into between:

Tranquil Veda Private Limited (operating as "Jarvis Daily"), a company incorporated in India, GSTIN 27AAHCT6956C1Z3, with registered office in Pune, Maharashtra ("Jarvis Daily" or "we"), and

Section 2

Engagement

Jarvis Daily will design, build, deploy, and maintain a custom dashboard and execution module ("AlgoVeda Dashboard" or "Platform") that mirrors the Client's Zerodha account activity across multiple configurations and implements the Client's specified R1 to R4 execution logic via Zerodha Kite Connect. This engagement covers the Client's specific requirements (dashboard, execution module, daily token utility, quantity multiplier, real-time parameter editor); it does not replace the Client's existing Tradetron setup, which the Client may continue to run as desired. The Client retains full operational and trading control. Jarvis Daily is the software vendor; the Client is the operator.

Section 3

Deliverables

3.1 Central Command Dashboard

Web application providing a per-configuration view (positions, P&L, active strategies, pending orders, today's trades) plus a cross-configuration aggregated view. Tab navigation between active configurations. Real-time updates via WebSocket subscription to the backend.

Acceptance: Dashboard renders 5 configurations on staging with live tick data from Kite Connect for 1 trading session without crashes or data loss.

3.2 R1-R4 Execution Module

Python execution module that implements the Client's specified R1 to R4 logic for the 4 to 5 strategies in scope, including the existing Natural Gas (MCX) configuration with 27 sets, refactored from the prior R1-R4 OMS engagement. Each strategy supports multiple independent sets with per-set entry and exit conditions.

Acceptance: Natural Gas strategy executes correctly on paper trading for 2 consecutive trading days with no manual intervention.

3.3 Daily Token Automation

Per-configuration Kite Connect access token refresh worker scheduled before 9:15 IST daily. Telegram alert on success and failure. The Client's nominated ops lead (Bhopesh) runs day-to-day token operations; Jarvis Daily provides the worker, the alerting, and platform-level fixes only.

Acceptance: Token refresh worker runs successfully for 5 configurations across 3 consecutive trading days.

3.4 Smart Execution Layer (R1-R4)

R1 Smart Entry (30-minute limit-fill window with partial-fill tracking and timeout fallback), R2 Instant Exit (sub-2-second market order on exit signal), R3 Partial Exits (tranche-based profit booking with configurable milestones), R4 Averaging Down (additional entries at better prices with configurable level caps). All R1-R4 logic is configurable per strategy.

Acceptance: Each of R1, R2, R3, R4 demonstrably fires on paper trading account against the Natural Gas strategy in line with configured thresholds.

3.5 Quantity Multiplier UI

Single slider in the dashboard that scales base quantity across active configurations in real time. Per-configuration absolute caps enforced server-side. Confirmation modal triggers above 1.5x. Values above 2x require a separate explicit unlock setting.

Acceptance: Multiplier changes propagate to active strategies within 5 seconds; hard caps prevent any order above configured per-configuration limits.

3.6 Real-Time Parameter Editor

UI to modify entry threshold, target, stop loss, and quantity parameters for any active strategy. Param changes take effect on the next signal evaluation. Changes logged to an append-only audit trail. 30-second confirmation cool-off on save.

Acceptance: Parameter changes propagate to running strategy within next evaluation cycle; audit trail captures every change with timestamp, user, before-value, after-value.

3.7 Audit Trail, Alerts, Kill Switch

Every order logged with reason, signal, price, fill status, and timestamp. Telegram alerts for: order rejections, failed token refresh, kill switch fires, margin shortfalls. One-click kill switch cancels all pending orders across configurations (does not auto-close existing positions).

Acceptance: Audit log captures 100% of order events across a 2-day paper-trade run; kill switch tested end-to-end.

3.8 Mumbai VPS Deployment with Static IP

Production deployment on Mumbai-located VPS with static IP registered against the Client's Kite Connect application per Zerodha's April 2025 requirement. SSL termination, NGINX reverse proxy, systemd service supervision, structured logging with rotation.

Acceptance: Platform reachable on production URL with valid SSL, services restart automatically on reboot, logs accessible to Client.

3.9 Handover Pack

At go-live: private GitHub repository invite, credentials vault transfer, runbook PDF, 2-hour live handover call with the Client's ops lead.

Acceptance: Handover call completed, repo access confirmed, runbook delivered.

Build duration:

5 to 6 weeks build + 2 weeks hardening and paper-trade UAT from kickoff. Target go-live: 15 July 2026.

Section 6

Monthly Retainer Scope

The Rs 15,000/month retainer covers:

  • Platform-level monitoring and uptime alerting during market hours.
  • Incident response for platform faults (target acknowledgement within 30 minutes during market hours; resolution within 4 hours for severity-1 incidents).
  • Minor parameter tuning, threshold adjustments, and bug fixes (up to 8 hours per month, cumulative).
  • Patches for Zerodha Kite API changes, library updates, security advisories.
  • Monthly health report summarising uptime, incidents, and any flagged anomalies.

Out of scope at retainer pricing: new strategies, major architectural changes, additional configuration onboarding logic, training of the Client's team beyond initial handover. These are scoped and quoted separately.

Section 12

Termination

12.1 By Client

The Client may terminate this SOW at any time on 30 days written notice. The setup fee is non-refundable. Monthly retainer is pro-rated for the termination month.

12.2 By Jarvis Daily for Convenience

Jarvis Daily may terminate this SOW on 30 days written notice. In such case, a pro-rata refund of any unused prepaid retainer is issued. Jarvis Daily will provide reasonable transition assistance during the notice period.

12.3 By Jarvis Daily on Regulatory Event

Jarvis Daily may terminate this SOW on 7 days written notice if Jarvis Daily receives any notice, summons, show-cause notice, or communication from SEBI, NSE, BSE, MCX, Zerodha, or any other regulatory or exchange authority concerning the Platform or the Client's use of it. In such case, the setup fee is non-refundable; retainer is pro-rated to the termination date; Jarvis Daily may immediately suspend Platform operation.

12.4 By Either Party for Material Breach

Either party may terminate this SOW on 14 days written notice in the event of a material breach by the other party that remains uncured at the end of the notice period.

12.5 Effect of Termination

Sections 8 (Client Compliance Representation), 10 (Indemnification), 11 (Limitation of Liability), 13 (Data Ownership and IP), 14 (Confidentiality), 16 (Governing Law), and 17 (Dispute Resolution) survive termination of this SOW indefinitely.

Data Ownership and Intellectual Property

Data Ownership

The Client owns all trading data, configuration data, strategy parameters, transaction records, and audit logs processed through the Platform. The Client retains full access and export rights at any time during the engagement and for 30 days after termination. All Client-account logins and operational credentials for the Platform will be handed over to the Client's team. Jarvis Daily will not use Client data for any purpose other than delivering the services under this SOW.

Intellectual Property

The Jarvis Daily AlgoVeda Platform (including its API, source code, system prompts, workflows, execution engine logic, dashboard framework, multi-configuration architecture, and underlying infrastructure) is a pre-existing product owned by Tranquil Veda Private Limited. Under this SOW, the Client is licensing a configured instance of the Platform for the duration of the engagement, and nothing in this engagement transfers ownership of the Platform to the Client or constitutes a work-for-hire arrangement under Section 17 of the Copyright Act 1957. The Client's own trading strategies, parameter values, and account configurations remain the Client's property.

Third-Party Service Providers

The service is delivered using reputable third-party providers (Zerodha Kite Connect, cloud hosting, Telegram for alerting). Each operates under its own terms and retains records per its own policies and applicable law. Jarvis Daily selects responsible providers but does not warrant third-party conduct or uptime. Jarvis Daily's total liability for sub-processor incidents is capped at fees paid in the preceding three months.
